## 0. 背景：为什么要重新做视觉，而不是"再加一层装饰"

站长部署完首页目录的自定义下拉（`cdff96b`）之后，陆续提了几轮反馈，原话摘录：

> 「除了那些在文档里特别提过的地方，还有很多是"假"定制，简单来说就是整个博客里面所有的从文字到颜色到美术材质，全部都要定制化」
> 「我整体看是喜欢的，但总能看到很多 AI 痕迹，以及感觉没有一种看一眼就记住的深刻印象」

**这不是"再挑个更好看的配色"能解决的问题**，是方向性的：现在整套"深蓝+烫金+复古衬线+皮革纹理+工程蓝图网格"
视觉，**每一个具体选择的依据都是"这样显得高级/有巧思"，没有一个是从"这个博客实际是什么"推出来的**。
这套配方本身这两年也已经变成另一种能被一眼认出来的通用模板感，不比"暖米色+衬线"更独特，只是更晚被用滥。

## 1. 已经跟站长确认的事实（后面所有设计决策都要能追溯回这几条，不能凭感觉加东西）

- **内容是什么**：站长原话——「blog blue 是我记录各种有趣图片的地方，也会发一些自己感兴趣的内容」。
  **这是一个以图片为主的博客，不是纯文字技术笔记**，这一点极其重要，下面第 3 节详细说为什么现在的实现完全没考虑这件事。
- **AAAduo 是谁**：站长原话——「AAA 多是我」。也就是说站点里那个签名词标、"NO.001 / AAAduo 的博客"这行字，
  指的就是正在和 AI 对话、拍板所有设计决定的这个人，不是一个虚构的人设。
- **站长对现状的真实态度**：「整体看是喜欢的」——**不是推翻重来**，是在现有基础上去掉"AI 痕迹"、
  补上"记忆点"。喜欢的部分不需要碰（配色的蓝色基调、烫金强调色、Fraunces 衬线标题字体这几个"锚点"
  站长没说要换，下面的方向也保留了这几条）。

## 2. 诊断：具体是哪两件事在制造"AI 痕迹"（不是笼统的感觉，是两条具体判断）

1. **"深蓝+烫金+复古衬线+皮革纹理"这套组合本身，已经是另一种通用配方**，选择依据是"什么显得高级"，
   不是"这个博客本身是什么"。皮革贴图是手工生成的没错，但"要不要做成皮革质感"这个决定本身没有专属性。
2. **"工程蓝图"这个概念被翻译成了最直白、最容易被认出来的那种视觉套路**：方格网纸背景、虚线标注、
   等宽字体到处贴"技术感"标签、卡片描边做成缝线——这些是"让人一眼觉得有巧思"的常见设计套路，
   套路一旦被认出来，"巧思"就变成"又是这一套"，这正是"记不住"的根源：**认得出手法，记不住内容**。

## 3. 一个具体证据：`cover_image` 字段存在，但从头到尾没有一个前台页面显示它

去代码里核实过，不是猜测：

- `db/schema.sql`：`posts` 表有 `cover_image VARCHAR(500)` 字段。
- `views/admin/editor.ejs:155-156`：后台写文章时可以填"封面图 URL"。
- `src/models/post.js:17,87`：**首页列表查询、目录查询都在 SELECT 这个字段**——数据一直被取出来了。
- 但前台只有 `views/partials/head.ejs:5,29` 用它拼 `<meta og:image>`/`twitter:card`——**只给社交媒体分享用**，
  真人访客从首页到文章详情页，**永远看不到这张图**。首页目录（无论是旧的 `.post-card` 列表还是新的
  `#notebook-book` 单页目录）都只渲染标题+日期+摘要文字，文章页正文里的图也只是随手插入的一张 `<img>`，
  没有任何构图/尺寸/呈现方式上的特殊处理。

一个"记录各种有趣图片"的博客，图片在设计里的地位跟一个纯文字技术博客毫无差别——**这是目前最大的一处
"表面很讲究、内核没对上"，也是任务 B 里优先级最高、最不该跳过的一项**，比任何颜色/材质的微调都重要。

## 4. 提议的新方向：从"工程蓝图"转向"蓝晒摄影工艺"（尚待站长看到实际效果后拍板）

站长的项目自述文档（`README.md`）里，视觉概念原本写的就是"blog + blue → **工程蓝图 / 蓝晒工艺
（cyanotype）**"，但实际实现只做了"工程蓝图"这一半，"蓝晒工艺"这半从没真的落地过。

**蓝晒工艺（cyanotype）本身是一种真实存在的摄影冲印工艺**：19 世纪常用，把感光的普鲁士蓝药水涂在纸上，
拿实物或底片在阳光下曝光冲印，成品是深普鲁士蓝底色 + 曝光不到的地方留白成剪影，边缘因为手工刷药水
而深浅不均、常带毛边（代表作是 Anna Atkins 用这个工艺拍的植物标本照片）。

**这条线索此前完全没有被用起来**，而它恰好直接对上站长博客的实际内容——"记录有趣图片"。如果把整套视觉
语言的落点从"图纸上的一处工程标注"，改成"每一张图都像刚从蓝晒显影出来的照片"：
- 蓝色基调、烫金强调色、Fraunces 标题字体这几个站长喜欢的"锚点"可以保留，不用推翻重来；
- 但材质从"皮革+方格图纸"换成"蓝晒相纸"：药水刷不均匀的深浅色边、曝光留白的剪影效果、太阳晒褪的
  做旧感——这些细节**是从"这是一个装照片的地方"这个事实里长出来的，不是又一层"显得有巧思"的装饰**；
- 首页目录、文章页都要围绕图片重新设计，把第 3 节发现的 `cover_image` 字段真正用起来。

**这个方向目前只是在聊天记录里跟站长文字层面对齐过，没有做过任何视觉稿**，下一个接手者做出第一版
实际效果后，必须让站长在真实浏览器里看过、给出"是不是这个感觉"的反馈再往下推进——不能因为方向
"已经确认"就一路做到底不回头对齐，这是这个项目一贯的协作方式（见 HANDOFF.md 第 3 节）。

## 5. 建议的执行顺序（不要一次性糊完，分批做、分批给站长看）

1. **先出 1-2 屏静态视觉稿**（可以是首页目录 + 一篇文章页），只做颜色/材质/排版，不用先接真实功能，
   让站长确认"蓝晒摄影工艺"这个具体呈现是不是他想要的记忆点，再决定要不要继续。
   ⚠️ 沙箱环境里 Google Fonts 访问不到、没有无头浏览器，视觉稿做完最好能让站长在真实浏览器里看，
   不要只凭代码"看起来应该对"就往下走（这条踩过坑，见 HANDOFF.md 第 6 节）。
2. 稿子定了之后，**首页目录改成图片优先**：用起 `cover_image`，标题+日期这套纯文字排版让位给图片。
3. **文章页的封面图/正文图给到真正的主角位置**，不再是正文里随手一张 `<img>`。
4. 再回头处理 `docs/HANDOFF.md` 里已经点过名、优先级较低的几处通用感元素（评论表单、空状态/错误提示、
   Markdown 任务列表复选框、404 页），这几处到时候直接套用新材质语言就行，不用单独重新设计一套。
5. 后台管理界面维持现状不动——`README.md` 里写明这是有意的设计决策（"后台优先好用，不上材质"），
   不在这次定制化范围内。

## 6. 还没有答案、下一个接手者需要自己判断或找站长确认的地方

- 蓝晒工艺的"曝光留白剪影"效果具体怎么在网页上实现（CSS 滤镜？预处理图片？纯装饰边框？），
  几种技术方案的效果和成本都要摆出来，不要选了最省事的那种就直接定稿。
- 首页目录改成图片优先之后，没有封面图的旧文章（比如"你好，blog.blue"那两篇）怎么显示——
  是留一个空的蓝晒占位质感，还是继续退回纯文字条目，这个也要考虑进设计稿。
- 评论表单、404 页这些"次要但确实通用感很重"的地方，具体做成什么样，等第 5 节的主线定稿后再细化，
  不要提前把它们也设计出来又被主线推翻。
