### 4. 部署（生产环境）


**这次部署实际踩到的两个坑（都已解决，但别再犯）：**

1. **不要用 root 直接操作这个仓库**。用 root 跑过一次 `git pull` 会让 `.git` 里出现 root 拥有的对象文件，之后 `blogblue` 用户 pull 会报 `insufficient permission for adding an object to repository database`。修复：`chown -R blogblue:blogblue /var/www/blog-blue`，此后所有 git/npm/pm2 操作都加 `sudo -u blogblue`。
2. **服务器上的文件必须只通过 `git pull` 更新**。v3 最初是拷贝文件上去的，git 把它们当成"本地未提交的改动"，后续 `git pull` 会拒绝合并（`Your local changes would be overwritten`）。处理方式：先 `tar` 备份 → `git diff <已知提交> --stat` 确认服务器上没有比仓库更新的内容 → `git reset --hard origin/main`。`.gitignore` 已经排除了 `.env`、`uploads/`、`logs/`、`node_modules/`，所以 reset 不会动它们。
3. 忘了跑 `npm run migrate` 不会出事：`src/app.js` 启动时会调用 `commentModel.ensureSchema()` 补上评论表的新列（幂等）。**但新增迁移时也要遵循这个习惯**：schema.sql 写成 `IF NOT EXISTS`，重要的再加启动兜底。

## v4 · 2026-09-20 · 评论审核重做（任务二，和 v3/v3.1 的视觉任务分开）

### 诉求

站长：以专业设计师的身份重新设计后台评论审核，建议把**文章和评论绑定**以便后续操作，具体由我分析和设计。

### 旧版的问题（分析）

1. **只有"待审核"一个视图**：通过 / 标垃圾之后评论就从界面上消失了。误点垃圾 = 永远看不到；没法回看已通过的；没法删除。
2. **评论和文章是脱节的**：一条评论只有一个文章标题链接。文章列表里看不出哪篇有待审评论；进评论页看不到"这篇文章一共有几条、说了什么"。
3. **每次操作整页刷新**回到顶部，处理 20 条 = 20 次刷新。
4. **作者不能回复**：表里有 `parent_id`，但从来没用过，评论是单向的。
5. 没有批量、没有键盘操作、看不出"是不是同一个人在刷"。
6. 评论功能默认是**关闭**的，评论页却完全不提示。
7. 侧栏没有待审数字，只有仪表盘顶部一条 banner。

### 设计思路

把它当成**邮件收件箱**来做（每天要重复做的分拣工作），并且**以文章为单位组织**：

- **信息架构**：`/admin/comments` 是全站收件箱（默认待审，先来先处理）；`/admin/comments?post=<id>` 是**文章绑定视图**——顶部是文章卡片（状态、三种数量、编辑文章/在站点查看），评论按**对话顺序**排列，回复缩进一层跟在上级下面。
- **左侧"按文章"栏**：只列有评论的文章，待审多的在前，带数字。
- **状态标签页**：待审核 / 已通过 / 垃圾 / 全部，数字跟着当前范围走（选了文章就是这篇的数字）。垃圾是**可恢复的暂存区**，永久删除只出现在垃圾箱和作者自己的回复上，并二次确认。
- **文章 ↔ 评论双向互链**：文章列表新增"评论"列（待审 pill + 已通过数，点了直接进该文章的评论）；文章编辑页右侧有"本文评论"入口；侧栏"评论"上有待审角标；评论卡片上有文章链接，已通过的评论有"在文章中查看"（跳到前台 `#c-<id>` 锚点并高亮）。
- **不刷新 + 可撤销**：所有动作是 fetch + JSON，服务端返回**重新渲染好的卡片 HTML**，前端只做替换（卡片长什么样只有 `views/partials/comment-card.ejs` 一处说了算）；通过/垃圾/退回后 7 秒内可撤销（按 `U` 也行），撤销会按原位置插回去。
- **键盘**：`J/K` 上下、`A` 通过、`S` 垃圾、`R` 回复、`X` 选择、`Ctrl/⌘+Enter` 发送回复。中文输入法组词时不拦截按键。
- **作者回复**：直接通过、标"作者"、前台也显示徽标并缩进；**回复一条待审评论 = 认可它**，上级会一并通过（一步完成"通过 + 回应"）。
- **访客识别**：卡片显示 `访客 #a3f9c1 · 共 N 条`（按 IP 哈希，不存明文）；同一访客有多条待审时出现"该访客的 N 条待审全部标垃圾"（已通过的不动）。
- **批量**：勾选后浮出操作条（通过/退回/垃圾/删除），"全选本页"。
- 评论关闭时页面顶部有提示和设置入口。

### 改了哪些文件

- `db/schema.sql`：`comments.is_author` 列 + 两个索引（可重复执行）。`src/models/comment.js` 的 `ensureSchema()` 在**应用启动时**也会跑同样的语句，所以即使忘了 `npm run migrate` 也不会 500。
- `src/models/comment.js`：重写（列表/统计/文章栏/线程排序/批量/回复/同访客）。
- `src/routes/admin.js`：`/comments`（GET）、`/comments/:id/status|delete|reply|spam-visitor`、`/comments/bulk`；侧栏角标中间件；仪表盘和编辑页带评论数。旧的 `/comments/:id/approve|spam` 已删除。
- `views/admin/comments.ejs`、`views/partials/comment-card.ejs`、`public/js/admin-comments.js`、`public/css/admin.css`（收件箱样式）。
- 前台 `views/post.ejs`、`src/routes/public.js`、`public/css/style.css`：评论按对话排序、作者徽标、`id="c-<id>"` 锚点。

### 顺手修的两个真问题

- **前台提交评论的 `parent_id` 没校验**：乱写一个值会让 Postgres 抛类型错误（500），指向别的文章的评论会把评论挂错地方。现在必须是合法 UUID 且是**同一篇文章里已通过**的评论，否则当作顶级评论。
- **CSP 会拦掉 `style="..."` 行内样式**（`styleSrc` 只有 self + nonce）。编辑页那个 `style="display:none"` 的文件输入在生产环境其实是显示出来的；已改成 `hidden` 属性。**其他视图里零星的行内 style（间距之类）同样不生效**，只是不影响功能，没有动。新代码里不要再写行内 style。

### 验证

这次装了真的 PostgreSQL 16，用**真实应用 + 真实 session/CSRF** 跑了：模型 25 项（含线程、级联删除、跨文章 parent 拒绝、批量、非法 id 安全）+ Playwright 端到端 40+ 项（登录、通过/撤销、键盘、同访客批量垃圾、垃圾箱恢复/永久删除、文章绑定视图、回复通过上级并嵌套、批量条、编辑页互链、前台线程/徽标/锚点、XSS 内容被转义）。全部通过。同时也**确认了 v3 的 `/admin/preview` 在真实 CSRF 链路下正常**。

## v3.1 · 2026-09-20 · 卡片质感修正：图与底分层

### 起因

站长看了 v3 后的反馈：靛蓝皮革桌面很舒服，但**文章卡片也是同一种粗粒皮革，读久了视觉疲劳，抓不住主体**。

### 判断

问题不在皮革本身，而在**整个画面只有一种质感，没有层级**：桌面（忙）和卡片（同样忙）在争夺注意力，正文压在最忙的那层上。
排版上的原则是"越靠近要读的东西越安静"，所以把质感分层：

桌面（有纹理、暗）→ 卡片边缘（粗粒、亮）→ 卡片中心（细腻小牛皮，几乎是平的、最亮）→ 文字

### 做了什么

- 新增一张 `leather-calf-v1.webp`（`tools/build-leather.js` 的 `calf` 配方）：粒极细（6px）、无褶皱、无毛孔、反差约 ±2–3%，离远看几乎是平的，凑近才觉得是皮。卡片正文区用它。
- 原来的粗粒 `leather-cream-v1.webp` **只留在卡片最外一圈**（文章 40px、列表卡片 30px、手机 20px/18px），向中心羽化消失；缝线正好落在这一圈里。实现是 `::after` 上一层粗粒背景 + 两条垂直渐变遮罩取并集（= 一圈羽化边框），`z-index:-1` 垫在正文下面。
- 卡片纸色略提亮（`#F6EFE0`），拉开和桌面的明度差，主体更突出。
- 后台预览面板同步换成 calf，保持"预览 = 发布后的样子"。
- 桌面（靛蓝皮 + 压痕线格）**没动**，站长明确说舒服。

### 坑

- 手机上卡片内边距只有 24px，粗粒边必须比它窄，否则会蹭到正文；已在媒体查询里收窄。
- `--rim` 不要大于卡片的 padding。改 padding 时记得一起看这个变量。
- 想调整"质感强度"，改 `calf` 配方的 `lightGain` / `strength`，然后 `npm run leather`，**并把文件名升到 `-v2`**（静态资源缓存 7 天）。

### 背景（founder 的原始诉求）

1. 写文章时要用到 `#`、`**`、`> ` 这类符号，希望编辑页有一张"使用表"

### 做了什么

**A. 写作系统（`views/admin/editor.ejs` + `public/js/admin.js` + `views/partials/md-cheatsheet.ejs`）**

- **工具栏**：H2/H3/H4、粗体/斜体/删除线/高亮/行内码、列表/编号/待办/引用/提示框、链接/图片/代码块/表格/分隔线。再点一次是取消，不是叠加。
- **使用表**（Ctrl+/）：右侧抽屉，"你写什么 → 得到什么"，**每一行可点击直接插入**，和工具栏走同一张 `COMMANDS` 表，行为不会不一致。另有"大纲"（按标题跳转）和"快捷键"两页。

- **安全网**：正文每 1.5 秒暂存到本机 localStorage，意外关页后再打开提示恢复；有未保存改动时离开页面会提醒；保存成功（`?saved=1`）后自动清掉暂存。

**B. Markdown 渲染新增语法（`src/utils/markdown.js`）**

- `==高亮==` → `<mark>`（前台是金色荧光笔下划）
- `> [!NOTE|TIP|WARN|IMPORTANT]` → 提示框（语法和 GitHub alert 一致，别处写的文字搬过来不用改）
- h2/h3 自动带锚点 id（中文标题保留汉字，重名自动加序号）
- 表格、任务清单、四级标题在前台补了样式（以前能渲染但没样式）

**C. 皮革视觉（`public/css/style.css` + `tools/build-leather.js`）**

概念叫"蓝图缝线"：靛蓝皮革桌垫 + 压进皮里的蓝图线格 + 象牙色粗粒植鞣革卡片 + 烫金缝线。

- 页面底：靛蓝细粒皮；线格不再是画上去的白线，而是**压痕**（每条线 = 一道暗槽 + 紧贴的一道高光），每 5 格一条主线，每个交点一个针孔（缝纫打孔定位的意象）；四角暗角。
- 文章卡片/列表卡片：象牙色粗粒皮 + 一圈等距烫金缝线 + 边油（边缘比面深）+ 旧化晕影；置顶标记改成燕尾书签丝带；代码块变成"嵌在皮里的深色小牛皮片"；文末有一枚盲压落款（同一份签名路径，只压凹痕不上色）。
- **底纹是离线生成的静态图**，不是 CSS/SVG 滤镜：`npm run leather` 用细胞噪声（每个粒面一个细胞，交界处是褶皱）→ 高度图 → 光照，得到真实的粒面；四边无缝。产物 `public/img/leather-navy-v1.webp`、`leather-cream-v1.webp`（各约 60KB）。

### 坑 / 判断依据

- **为什么不用 feTurbulence**：各浏览器栅格化不一致，长文章滚动会掉帧，而且它给的是"脏"不是"粒"。
- **卡片底纹上盖了一层 34% 的奶油色**：第一版粒面反差太高，正文压在上面很累。改粒面视觉时先在真实正文上看可读性，别只看纹理好不好看。
- **改了底纹配方要换文件名**（`-v1` → `-v2`）：静态资源缓存 7 天，`style.css` 里的图片 URL 没法带 `?v=`。
- **`/admin/preview` 单独限流**：全站限流是 120 次/分钟，实时预览会把它吃光，连带保存按钮一起被限流。所以 `globalLimiter` 跳过它，由 `previewLimiter`（240 次/分钟，先于登录校验）兜底。
- **中文输入法**：所有键盘拦截都先判断 `isComposing` / `keyCode 229`，否则回车会在确认候选词的同时被当成"续列表"，吃掉正在打的字。
- **历史文章的 `content_html` 是保存时渲染好的**：新语法（高亮、提示框、锚点）对老文章要重新保存一次才生效。
- **CSS 里的 `[hidden]`**：元素自己写了 `display` 会盖掉浏览器默认的 `[hidden]{display:none}`，`admin.css` 末尾加了全局兜底。
- 字体（Fraunces 等）来自 Google Fonts，我这边的测试环境访问不到，所以**中文/英文字体的最终观感没在我这边确认过**，部署后请看一眼。

### 验证过什么

- 用 Playwright 驱动真实的 `editor.ejs` + 真实的 `renderMarkdown` 跑了 40 多项：每个工具栏命令（含取消）、粗体套斜体、标题互转、列表互转、智能回车/Tab、块前后空行、Ctrl+Z 能撤回工具栏操作、预览渲染、抽屉插入、大纲跳过代码块、草稿恢复、粘贴图片占位符、保存后清暂存、专注模式。全部通过。

## v2 · 2026-09-19 · 品牌签名标识 + 图片水印防伪

### 背景（founder 的原始诉求）

1. 水印没贴正
2. logo（词标 + 水印）重新设计，只要 "blog.blue"，换成艺术签名字体，要专属、不要烂大街
3. 以防伪专家的视角给水印加防伪措施和艺术感，但**不要明显**

### 做了什么

**1. `src/utils/brand.js`（新增，整个品牌标识的唯一真源）**

以前页眉词标、favicon、图片水印是三份各自手写的 SVG，改一处忘两处。现在三者都从这一个文件生成。

字形：整个 "blog.blue" 不是任何一款字体，是手工拟合的**单线条连笔签名**，全部由三次贝塞尔曲线构成（`GLYPHS` 数组，一条路径一个字母；`FLOURISH` 是收尾甩出去再横扫回来的那一笔）。

为什么不用字体：
- 专属性——别人装不上"同一款字体"就复刻不了
- 服务端渲染水印时不依赖服务器装了什么字体（旧版在服务器上退化成 DejaVu Serif，很难看）
- 手写曲线的控制点是不规则的，肉眼描摹必然走形——这本身就是第一道防伪

字形调过很多版，踩过的坑记一下，免得下次白走：
- 纯连笔草书的 `b` 会被读成 `l` + `e`（"blog" 看起来像 "lelog"）。最终方案是**混合体**：上伸部走细长环（签名感），碗形做成闭合的印刷体碗（可读性）。改 `b` 的时候务必渲染出图看一眼，不要只改数字。
- `o` / `g` 收笔处如果让路径折回，渲染出来会有个小疙瘩。现在是收笔到 x 高度就停，出锋另起一笔。

**2. 四层防伪（`brand.js` 里的 `guilloche` / `rosette` / `tickCode` / `microtext`）**

设计原则：真正管用的防伪从来不是"加个显眼的封条"，而是几层彼此独立、单独看都像装饰、合起来才能判真伪的细节。

| 层 | 是什么 | 正常观看时 | 怎么查 |
|---|---|---|---|
| L1 | 手工曲线字形 | 就是个签名 | 逐笔比曲线，描摹的必走形 |
| L2 | 扭索纹 guilloché | 纸面上一点织纹（16% 不透明度） | 放大看是连续的外摆线；R/rr/d 三个参数写死在代码里，从图片反推不出来 |
| L3 | 微缩文字 | 一条发丝线 | 放大原图 300% 以上能读出重复的 "blog.blue" |
| L4 | 刻度暗码 | 蓝图上的一段比例尺 | 基线下 16 个刻度，长=1 短=0，编码每张图唯一的序列号 |
| L5 | 陷阱 | 看不出来 | 微缩文字里每 4 个循环节有一处"错字"，位置由序列号决定 |

L5 是专门对付翻印的：对方照着"看起来像 blog.blue 的一行小字"重排，只会得到一行干净的正确文本——**没有错字反而说明是假的**。

**关键实现细节（改动时最容易踩的坑）**：L3/L4 的尺寸是按**输出像素**反推的，不是按设计坐标系。`u = box.w / width` 表示一个输出像素相当于多少设计单位，微缩文字字号 = `4.0 * u`。这样水印无论缩放到多大，微缩文字在最终位图里始终落在 4px 上下——太小会被栅格化成一团灰（防伪层直接失效），太大就不叫微缩文字了。**如果以后改水印尺寸逻辑，必须重新验证微缩文字在实际输出图上还能不能读出来。**

序列号 = `HMAC-SHA256(WATERMARK_SECRET, 文件名)`，**不入库、不存表**。只要 secret 没变，任何时候拿原图都能重算。上传时会打进 pm2 日志（`[watermark] <文件名> 序列号 XXXXXX`）。

**3. 水印贴图逻辑（`src/utils/watermark.js` 重写）**

"水印没贴正"的根因：旧版画布是写死的 402×160 圆角矩形，字形只占左边一半，右边空出一大片，看起来就是贴歪了。

修法：
- 按内容真实包围盒 + 四边等量留白（PAD=22）反推 viewBox，**居中是算出来的，不是眼估的**
- 贴图从 `gravity: 'southeast'` 改成显式 `left`/`top`，留白按图片短边算（竖图横图看起来才是同一个留白）
- 位置可配：`WATERMARK_POSITION` = southeast(默认)/southwest/northeast/northwest/center
- 去掉了那个半透明圆角底板——它既是"贴歪"观感的来源，也是最容易被干净裁掉的东西

新增**自适应配色**：贴之前先用 `sharp().extract().stats()` 量落点区域亮度，亮度 > 0.55 用墨色笔画 + 浅色底衬，否则白色笔画 + 深色底衬。固定白色在雪景/白墙/米色纸面上会直接消失，**水印看不见等于防伪层也一起没了**。

底衬用"同路径描粗一遍"而不是 SVG 滤镜——服务端 librsvg 对滤镜的支持比对描边脆弱得多。

尺寸规则：宽度 = 图宽 × 26%，下限 150px（实测微缩文字还能读出来的最小尺寸），上限 320px。图太小（水印宽 > 图宽 55% 或高 > 图高 40%）直接跳过不打。GIF 仍然不打（sharp 合成会把动图压成单帧）。

**4. 查证工具 `tools/verify-watermark.js`**

```bash
npm run wm:verify -- <文件名>                    # 打印序列号 / 刻度码 / 陷阱位置
npm run wm:verify -- <文件名> --png /tmp/ref.png  # 再生成一张对照水印图
```

必须在服务器上跑（要读 `.env` 里的 secret）。序列号的依据是**文件名**不是路径，所以拿着从网上下载回来的图（只要文件名没被改）也能算。

**5. 其他连带改动**

- `public/favicon.svg`：改成签名里的 `b` 单字 + 域名点，笔画比签名本体粗一档（16px 下细节会糊）
- `public/img/og-default.png`：用新签名重新生成（1200×630，蓝图网格 + 图框角标）
- `public/css/style.css`：词标颜色不再在 CSS 里重复定义（服务端生成时已写在属性上，两处定义必然不同步）；hover 时收尾那一笔会重新描一遍（`stroke-dasharray` 动画，`prefers-reduced-motion` 下不跑）
- `src/app.js`：新增 `res.locals.signatureMark(opts)` 助手（EJS 里没法 require）
- `views/partials/wordmark.ejs`：从 30 行手写 SVG 变成一行调用
