# 首页"翻书"改版 · 设计规格

> 本文档记录首页从"卡片列表"改造为"翻页手帐"的设定、约束与执行计划。

## 0. 背景与目标

首页现在用"一版版卡片列表"展示文章，站长认为这种展示方式无聊。目标是把首页改造成一本可以翻页浏览的"手帐"：
左上角保留 blog blue 签名，下方保留网站信息，主体区域用翻书的方式展示文章目录，点击目录条目进入文章全文页。

**范围限定：仅改动桌面端（电脑版）。移动端保留现有卡片列表，不做改动。**

---

## 1. 核心设定（已与站长确认）

- 这不是"工程师工作日志"，而是**站长自己的日记/手帐**：随手记录一些有趣的照片或文字，语气轻松、非正式。
- **载体必须延续 blog.blue 已有的品牌语言**：深蓝/蓝图配色、白线注记、纸张裁角、连笔签名字体系统（见 `src/utils/brand.js`）。
  手帐是"形式"（翻页、贴照片、写心情），蓝图是"材质和语言"——不能因为做手帐就滑向粉色系/樱花系/马卡龙的通用手帐视觉。
- 站长本人**不是专业或长期的手帐使用者**，是借这个项目学着做。设计基调应该是"认真但不算精通的新手在尝试"，
  不要做成"资深手帐玩家"那种过于娴熟、装饰过度精致的效果——装饰要克制、留白要多、偶尔的不完全对齐是合理的，
  这种"略带笨拙的认真"本身就是真实感来源。
- 标题/心情批注可以用比现有连笔签名更活泼一些的**艺术字体变体**；但目录列表正文、摘录文字必须保证清晰可读，
  不能为了美术效果牺牲阅读体验。**分层用字原则：标题用艺术字，正文/摘录用清晰易读字体。**

## 2. 明确的禁忌（站长直接指出的 AI 常见坑）

这些是硬约束，任何一步产出（原型/代码/文案）都要对照检查：

1. **不要自动加常见的 AI 交互套路**：书本体和便签本身**不应该有 hover 悬浮/高亮特效**。
   现实中的书和便签是静止的物件，不会因为鼠标靠近就悬浮起来。
   如果确实需要交互反馈（比如便签"可以被拿起来"），要用更贴近真实动作的效果（掀开一角、被拖拽），
   而不是数字界面式的 hover 高亮/放大/发光。
2. **拒绝"很新的旧"**：做旧不能是整体套一层滤镜/降低饱和度。真实的旧物磨损是**不均匀、不对称、有使用逻辑的**：
   - 磨损集中在最常被碰到的地方（书角、书脊、最常翻的那几页边缘），不是整体均匀泛黄
   - 材质之间要有"化学反应式"的旧痕（比如金属大头针在纸上留下的锈斑晕染、胶带老化后底下纸张的变色范围比胶带本身大一点、
     翻页多的地方纸张纤维起毛发白）
   - 这种"有因果关系的旧"比"滤镜式的旧"更可信，也更难被一眼看穿是 AI 做的
3. **不要把不属于这个设定的现代美学元素做旧后混进来**：所有装饰元素（胶带样式、便签材质、字体、图片装饰）
   都要能被"这是站长自己的蓝图手帐"这个设定解释，不要因为"好看"就添加跟设定无关的复古元素
   （比如突然出现和蓝图调性无关的花纹、或明显是数码时代产物却强行做旧）。

## 3. 目录页（书的主体）

- 每页目录页放 4–6 篇文章条目，非严格网格对齐，模拟手写记录的随性排布。
- 每条目录包含：标题（可用艺术字体）、日期（手写批注式，斜放）、一两句摘录（清晰易读字体）。
- 纸张要有轻微纹理，磨损遵循第 2 节的"不均匀"原则（书角/书脊先旧）。
- **分册**：按年/季度分册，默认打开最新一册并翻到最新一页。历史册子通过书脊上的可点标签切换。

## 4. 图片装饰系统

图片"贴"在页面上而非规整嵌入，装饰方式按文章 ID 做确定性 hash 分配（同一篇文章每次显示的贴法一致，不随机刷新变化）：

- 胶带贴（角度随机 ±3°~±10°，胶带边缘轻微卷起发黄，中段颜色变化最小）
- 拍立得式白框（底部留白可放一行手写小字图注）
- 大头针/回形针别住（适合截图类竖版图，考虑第 2 节提到的锈斑晕染细节）

**约束**：纯 CSS 实现（伪元素+滤镜+阴影），不额外增加图片请求；不能对图片本身加 hover 特效。

## 5. 标签/搜索 —— 便签系统

- 夹在目录页外围、露出一角，角上要有可辨识的图形/文字暗示内容（不能是纯色三角形让人瞎猜）。
- 样式池（随机分配，避免所有便签长一样，但都要落在蓝图手帐设定内）：方形便签、卡片式索引卡、书签丝带、回形针夹的小纸条。
- 交互：**不用 hover 高亮**，改用更接近"用手碰它"的动作反馈（被拖拽/掀开一角展开抽屉），点击/拖拽后才展开标签云或搜索框。

## 6. 翻页与跳转动效

两级区分清楚：

- **目录页之间翻页**（上一页/下一页）：慢速，模拟真实翻书的物理感（CSS 3D transform），用户主动触发。
- **点击目录条目 → 进入文章全文页**：快速的"哗啦啦翻过一叠纸"效果，营造穿越书页的仪式感，
  控制在 0.6–1 秒内；动画期间异步预取全文内容，动画结束内容同步到位，不能让用户等待感知延迟。

## 7. 技术与 SEO（Claude 自行裁定的部分）

- 底层保持服务端渲染的真实文章列表 + `<a href>` 链接不变，翻书效果是视觉增强层：CSS 3D + 少量 JS 控制状态。
- 无 JS 环境 / 搜索引擎爬虫：直接看到朴素的文章列表兜底（保留现有语义化 HTML 结构）。
- 现有的 sitemap.xml、`/feed.xml`、结构化数据、`/sitemap` 人看的站点地图页**全部保留不动**。
- 标题层级（h1/h2）不因为翻书视觉而错乱。
- 移动端完全保留现有实现，仅在桌面端做媒体查询分支接入新样式。

## 8. 协作方式（站长明确要求，本任务专用）

- **一步一步做，每步先分析再操作，可以慢但不可以求快**。不要一次性把整个功能写完再展示。
- 每一步分析要综合**设计师 / 美术家 / 程序员 / 产品经理**多个角度。
- 设计类判断要说清判断依据，且随时准备被站长的审美反馈推翻重做。
