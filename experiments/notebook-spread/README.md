## 现在这里有什么

- `gen-page-textures.js`：内页"痕迹故事"材质生成脚本，**原样复制自**
  `experiments/book-materials/page-variants.js`（那份没被否决的部分——发霉方向被
  推翻后改成的茶渍/水渍/晒痕/包浆五变体，算法本身站长已确认过，这里只是换了个
  输出目录，没有改算法）。跑法：`node experiments/notebook-spread/gen-page-textures.js`，
  会在本目录生成 `P0-clean.png` ~ `P4-handling-patina.png` 五张贴图。
- `build-spread-prototype.js` → `spread-prototype.html`：**步骤3的最小验证**。
  左页是缩小复用的封面（`notebook-cover` 那套原样搬过来），右页是一页目录，用
  P1（茶渍）内页材质 + 4条占位目录随性排布 + 标题艺术字/正文清晰字体分层。
  只做了一页，**没有**做多痕迹页对比、没有做书脊分册标签——这两项还是
  `docs/BOOK_DESIGN.md` 步骤3 里没做完的部分，跳过了，不是做完了。
- `build-flip-transition-prototype.js` → `flip-transition-prototype.html`：
  **步骤5**，点击目录条目触发"哗啦啦翻过一叠纸"动效，取4张不同痕迹的内页材质
  错开快速翻过，总时长 0.7s（落在规格要求的 0.6–1s 区间），用假延迟
  （550–750ms 随机）模拟异步取全文内容，动画结束和内容到达两者时长故意做得
  接近，用来验证"内容比动画早到/晚到"两种情况下都不会让用户看到空白或跳变。

## 步骤3剩余项补充（2026-09-23）

- `build-patina-comparison-prototype.js` → `patina-comparison-prototype.html`：
  **多痕迹页对比**。同一份排版和文字内容，唯一变量是 P0~P4 贴图，横排对比。
  结论（供站长判断，不是我自己拍板）：五种痕迹在目录页这个尺寸下**差异比预期更细微**——
  茶渍/水渍/晒痕/包浆肉眼要凑近看才分得出，不确定这是"克制得体"还是"做了等于没做"，
  这是审美判断，需要站长看实图定。文字可读性没问题，五种贴图上黑色系正文都够清楚，
  这条可以放心。
- `build-spine-tabs-prototype.js` → `spine-tabs-prototype.html`：
  **书脊分册标签**。在装订缝（`.gutter`）位置加 4 片竖排文字标签，代表 4 个分册。
  设计判断（都未确认）：
  - 当前分册标签**伸出更多、磨损更重**（不是更干净）表示"被翻得最多"，历史册子依次
    收进去、颜色转淡——对应第2节禁忌"磨损不均匀"，但这个"当前=最脏"的直觉可能需要
    站长确认是否认可，不是不言自明的选择。
  - **没有做 hover 效果**，"当前"状态完全靠伸出长度+磨损叠加两个静态信号表达，符合
    禁忌1，但代价是标签本身视觉上偏"扁平矩形卡片"，还是有点像网页侧边栏 tab，
    "物理贴纸感"不够强，这一点我不满意，需要站长看实图判断能不能接受，
    还是要往回形针/丝带书签那类更手作的方向改。
  - 标签文字用 `writing-mode: vertical-rl`，年份数字会横向躺着嵌在竖排文字里，
    36px 宽度下数字基本不可辨认——如果站长要求分册标签本身就能看清年份，这里要改
    （比如只在当前标签显示完整"2026·秋"，历史标签只显示"夏/春/冬"单字，年份放跨页顶部
    `toc-header` 里已经有的位置）。
  - 点击切换分册的交互完全没接（纯静态展示当前态），交互留给步骤4/6。

## 步骤4后端补充（2026-09-23）

真实数据接入的**后端部分**已完成，前端仍是假数据，这两件事分开进度记：

- `src/models/post.js` 新增 `listVolumes` / `listByVolume` / `countByVolume`——分册按
  `published_at` 的年/季度现算（`CEIL(月份/3.0)`），数据库里没有单独的分册字段。
- `src/routes/public.js` 新增三个只读 JSON 接口：
  - `GET /api/notebook/volumes` —— 书脊标签用，返回有文章的年/季度列表（新到旧）
  - `GET /api/notebook/toc?year=&quarter=&page=` —— 目录页用，每页6篇（对应设计规格
    "4-6篇"的上限）
  - `GET /api/notebook/article/:slug` —— 步骤5翻页动效用，只给文章片段（标题/HTML/
    标签），**故意不复用** `/p/:slug` 的渲染逻辑、也故意不在这里累加阅读量（真实阅读量
    应该算在访问 `/p/:slug` 那次，这里只是换内容，前端换上内容后要不要补一次静默计数
    还没做，是个小 TODO）
- 用临时 Postgres + 手工插入跨季度的测试文章验证过：分册分组正确、草稿不会出现在任何
  接口里、`year`/`quarter` 缺失或越界（比如 quarter=9）返回 400、超出范围的分页返回空
  `entries` 而不是报错、**首页 `/` 的服务端渲染列表不受影响**（无 JS/爬虫兜底没被动到）。
- **没做的**：前端完全没接这三个接口。`spread-prototype.html` 里的4条目录、
  `flip-transition-prototype.html` 里的 `setTimeout(fakeLatency)`、`spine-tabs-prototype.html`
  里的4个分册标签，都还是硬编码假数据，需要下一轮把它们换成真实 fetch。

## 步骤4前端对接补充（2026-09-23，第二轮）

只做了**书脊分册标签这一个原型**的对接，没有动 `spread-prototype.html` /
`flip-transition-prototype.html`——一步一步来，这两个还是假数据，是下一轮的事，
不要看到这节标题以为整个步骤4前端都接完了。

- `build-spine-tabs-prototype.js` 生成的页面不再写死 `VOLUMES`/`ENTRIES`，改成
  加载后用 `fetch('/api/notebook/volumes')` 和 `fetch('/api/notebook/toc?...')`
  读真实数据；点击标签会切换分册、重新拉取该分册第1页目录。
- 补上了"点击切换分册"的交互（上一轮标注的"交互留给步骤4/6"里步骤4这部分）。
- 因为要发真实请求，**不能再直接双击本地文件打开**（`file://` 下 fetch 相对路径
  会被浏览器当跨源拦掉）。新增了一条**仅开发环境**的静态路由
  `src/routes/public.js` 里 `if (process.env.NODE_ENV !== 'production')` 包住的
  `/dev/notebook/*`，把这个目录原样透出去。跑 `npm run dev`，浏览器开
  `http://localhost:3000/dev/notebook/spine-tabs-prototype.html` 就是同源。
  已经手工验证过：`NODE_ENV=production` 时这条路由是 404，`/api/notebook/*`
  三个正式接口不受影响；本地起了一份临时 Postgres + 跨季度测试文章，三个接口的
  返回结构、400/404 情况都又核对了一遍，和步骤4后端那节记录的一致，没发现新问题。
- **磨损（`--wear`）和"当前选中"（`.active`）拆成了两件独立的事**（本轮新加的
  工程判断，未与站长确认）：`.active`（标签伸出更多）跟着点击走，磨损深浅是
  每个分册固定的属性、按新旧顺序线性插值，不随点击变化——磨损记录"平时翻不翻"，
  不是"这一刻在不在看"。如果站长觉得"点开哪本哪本就该显脏"更直觉，这里要改。
  代码注释里写了同样的说明，改的时候一起看。
- 还没做：分页控件（现在只取每个分册第1页）、点目录条目的反应（步骤5的翻页动效
  还没并进来）、书脊标签本身"物理贴纸感不够、有点像网页侧边栏 tab"这条上一轮
  就提过的美术顾虑还没处理。
- 没能力做的：视觉截图确认——这一轮的沙箱环境下载不了 headless 浏览器
  （Playwright 的 Chromium 下载源不在允许访问的域名列表里），只验证了接口数据
  和 DOM 结构是对的，没能像 v3/v4 那样截图看实际观感，这条请站长本地打开后确认。

## 步骤5动效目前的坑 / 下一步

- **这段动效是假数据触发的**，用 `setTimeout` 模拟异步延迟。步骤4把真实文章
  数据和路由接上之后，这里要重新接线：把 `setTimeout(fakeLatency)` 换成真实的
  `fetch(slug)` 完成时机，动效本身（错开时间、旋转轨迹、总时长）不用大改，
  只是触发信号源要换。
- 还没问过站长这版动效的手感——时长、翻页轨迹、内容淡入方式都可能要调，
  站长看过后暂未给出具体反馈就要求先提交上传，**不代表定稿**。
- 只做了"点击进入"这一个方向，没做"返回目录"的对应动效（如果需要对称的
  反向动效，是步骤5的补充项，还没排期）。
